# 实施计划

1. 盘点仓库结构、技术栈、规范目录和现存工作树变更；不读取已删除 `.env`，以当前代码与测试为依据。
2. 检查后端 API、文件任务与实时会话生命周期、配置、安全、ASR providers、部署边界和测试覆盖。
3. 检查前端导航、文件转写/校对/导出、实时识别、历史、合并、配置与监控间的流程衔接、错误反馈、响应式及可访问性。
4. 对照 Buzz、WhisperX 等成熟开源项目的一手仓库文档，只采纳与现有产品定位相符的工作流模式。
5. 并行实施互不重叠的改进：
   - 文件任务：保存当前 task ID；启动时恢复状态并重连可重放 SSE；若轮询先发现任务终态，则从结果 API 补全 segments/text 并收敛状态。历史选择复用恢复逻辑但不取消原后台任务。
   - 实时识别：为麦克风录音及高级文件模拟器提供有禁用态和成功反馈的完整文稿复制、TXT 下载；短暂 SSE 断线保持采集/上传，重连从空基线消费服务端回放，避免累加重复文本。
   - 配置档案：分离 file 与 realtime provider 字段和其 endpoint 参数，兼容读取旧档案并验证激活后两种 provider 的行为。
   - 模型探测：自定义 base URL 不匹配已配置 endpoint 时不得自动复用服务端已保存密钥；覆盖新 endpoint、自定义密钥和已配置 endpoint 三条路径。
6. 对各改动运行针对性测试，再运行后端/前端全套测试、前端类型检查/构建；用浏览器检查桌面和窄屏交互。
7. 独立审查最终 diff，形成 `review.md`：总评、P0/P1/P2 证据、开源对照、已完成改进、残余风险与验证结果。
8. 回馈确有复用价值的项目规范（若有），归档任务；提交任务归档时只提交任务记录，避免夹带已有 staged 用户改动。
9. 继续收尾审查发现的 P1：默认本机绑定与 Compose loopback 发布、远程暴露鉴权说明、模型探测仅访问当前/已保存档案 endpoint（保留显式内网 ASR）、multipart 解析前按 `MAX_UPLOAD_BYTES + 64 KiB` 限制请求体，并保护 `/metrics`；加入针对性测试并重跑全套验证后重新归档。
